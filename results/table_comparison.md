# 调度策略对比结果（trace 驱动）

数据来源：Alibaba PAI cluster-trace-gpu-v2020（公开，sha256 已校验）。
每个 instance = 一个真实 6 小时繁忙窗口内的到达流 + 按 machine_spec 切出的真实机器分区。

关于 GPU 空闲率，本报告给出三个口径，因为它们会给出三种结论：

1. **固定窗口空闲率**：分母是模型时域的卡时。只要所有作业最终都跑完，已分配卡时就恒等于需求卡时，该值与策略无关（正好等于 1 − ρ），只能用来核对负载，不能用来评判调度质量。
2. **自身忙期空闲率**：分母换成该策略自己的 makespan，于是压缩 makespan 的策略会变好，但它奖励“早点收工”而与浪费无关，只作次级视角。
3. **带积压空闲卡时**：作业已经提交且仍在排队时，未被分配出去的 GPU 卡时。其中只有当某个排队作业在该槽位能同时放下它的 GPU/CPU/内存需求时，这份空闲才是调度器真正可以消掉的浪费，因此同时报告**总量**与**其中可利用**两项；表中的差值与所有图都使用“可利用”口径。队头阻塞制造可利用浪费，重排消除它，把作业推到时域之外会重新制造它。
